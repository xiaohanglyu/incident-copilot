# 路线图

[English](ROADMAP.md) · **简体中文**

## 终点

一个像 on-call 工程师那样调查线上故障的 Agent：从各个系统取数、跨源关联、形成排序过的
假设，并给出由人批准或否决的建议动作。

```
Prometheus · Kubernetes · Loki · Elasticsearch · Datadog · GitHub · PagerDuty
                              │
                        工具 / 适配层
                              │
                            Agent
                    ┌─────────┴─────────┐
                  收集数据            执行诊断
                    └─────────┬─────────┘
                            证据
                              │
                            假设
                              │
                          建议动作
                              │
                           人工审阅
                              │
                          批准 / 否决
```

Agent 永远不写入。任何动作离开系统时都只是建议。

## 阶段 1 — 可运行 demo 🚧

这个项目存在的三个理由，端到端跑通。

- [ ] 三个工具的固定样例数据，且必须互相咬合 —— 时间戳、指标拐点与发布时间要对得上，
      否则模型推不出预期的结论
- [ ] 启动时完成 Markdown 切分、向量化与索引
- [ ] 由代码显式检索并拼入 prompt，命中结果可在报告中引用
- [ ] 结构化输出绑定到 `Report`
- [ ] 一个写进文档的示例请求，能产出稳定的回答

完成标准：同一个查询，多次运行返回相同的结构与相同的结论。

## 阶段 2 — 真实适配器

## 阶段 3 — 持久化知识

- [ ] 用 pgvector 替换内存向量库
- [ ] 复盘写入接口，取代仅在启动时索引

## 阶段 4 — Agent 循环

- [ ] 从单次调用改为「收集 → 假设 → 再收集」
- [ ] 排序过的多个假设，允许「证据不足」作为合法结论
- [ ] 按假设驱动的二次检索
- [ ] 轮次与 token 预算

## 阶段 5 — 审阅流程

- [ ] 调查结果落库，不再每次重算
- [ ] 建议动作转为可审阅的记录
- [ ] 批准 / 否决，并保留审计轨迹

## 阶段 6 — 可运维性

- [ ] 长调查支持流式或轮询
- [ ] 单次调查的 token 与成本统计
- [ ] 跨工具调用的链路追踪
- [ ] 可选：把同一批工具暴露为 MCP，供外部 agent 调用
